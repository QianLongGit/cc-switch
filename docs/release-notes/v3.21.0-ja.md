# CC Switch v3.21.0

> 本リリースの新機能は **プロジェクト単位のプロバイダールーティング** です。Claude Code で複数のプロジェクトを並行して進めているとき、それぞれのプロジェクトに固有のプロバイダーを固定できます。CC Switch は `~/.claude` 配下の 3 つのソースを統合してプロジェクト一覧を自動検出し、新設の「プロジェクトルーティング」ページでプロジェクトをプロバイダーに紐付けます。紐付けはプロジェクト自身の `.claude/settings.local.json` に書き込まれ、ローカルプロキシ経由のリクエストが `X-CC-Project` マーカーを運ぶと、紐付けたプロバイダーが優先されます。紐付けは「ソフト」です。紐付け先が失敗すれば共有フェイルオーバーキューへ順に委ねられ、すべて遮断されても共有キューが救済し、紐付けたプロバイダーを削除すれば自動的に元に戻ります。リクエストログにはプロジェクト列・「ルート」バッジ・プロジェクト絞り込みが加わり、あわせて画像ブランチを通ったリクエストに「[画像]」バッジが付くようになりました。第一期は Claude アプリのみで、プロキシテイクオーバーの有効化が前提です。**本リリースにはデータベース移行（v19 → v21）が含まれます。アップグレード前に手動でバックアップすることをおすすめします** — [アップグレードノート](#本リリースにはデータベース移行が含まれます) を参照してください。

## ハイライト：このバージョンでできること

- **プロジェクトごとにプロバイダーを固定**：新設の「プロジェクトルーティング」ページ（Claude アプリ専用エントリー。セッションブラウザーと MCP ボタンの間にあります）。プロジェクトごとに 1 行：プロジェクト名・最終アクティビティ・プロバイダー選択・同期状態。「デフォルト（紐付けなし）」を選べばグローバルルーティングに戻ります。
- **プロジェクトの手動登録は不要**：プロジェクト一覧は `~/.claude` の 3 ソースから自動検出されます —— `~/.claude.json` の `projects` キー（権威あるパス一覧）、`~/.claude/projects/*/` 配下のセッション jsonl、`~/.claude/sessions/*.json` のアクティブマーカー —— アクティビティ順に並び、30 日以上動きのないものは除外。ページを開いている間は 3 秒ごとに自動更新されます。
- **紐付け先の失敗で詰まない**：ソフトバインディングの意味論。フェイルオーバー有効時は紐付け先が先頭に立ち、共有キューが重複を除いて続きます。紐付け先が失敗または遮断されれば共有キューへ委ねられ、全遮断時の共有キューによる救済はそのまま生きます。紐付けたプロバイダーを削除しても、ルーティングは紐付けなしとして共有キューに戻り、ページは黙って消すのではなく「無効」と表示します。
- **リクエストがどのプロジェクトから来たかを確認**：リクエストログにプロジェクト列が加わり、プロジェクト紐付けにヒットしたリクエストには「ルート」バッジが付き、プロジェクトでの絞り込みができます。
- **紐付けとファイルの一致がひと目で分かる**：同期 3 状態（同期済み / 未同期 / 孤儿ヘッダー）。「未同期」はワンクリックで修復、「孤儿ヘッダー」は任意でクリアできます。
- **画像ブランチのリクエストを識別**：画像ルート（vision）を通ったリクエストは、リクエストログのモデル列に「[画像]」バッジで示されます。

## 概要

「プロジェクト単位のプロバイダールーティング」が解消するのは、複数プロジェクト並行時の切り替えの手間です。これまでプロバイダー選択はアプリ全体で一つであり、プロジェクトを変えるたびにカードを切り替える必要がありました。これからは Claude Code の各セッションが自分のプロジェクト識別を運びます —— CC Switch はプロジェクトの `.claude/settings.local.json` の `env.ANTHROPIC_CUSTOM_HEADERS` 複数行値に `X-CC-Project: <percent-encoded パス>` の 1 行を注入し、ローカルプロキシがこのマーカーを読んで、そのプロジェクトに紐付けたプロバイダーへリクエストを振り分けます。

書き込みは慎重です。`X-CC-Project` の 1 行だけを追加・置換・削除し、同じ複数行値の中のユーザー自身のヘッダー行、ファイル内の他の env キーとトップレベルキーはバイト単位で保持されます。ファイルがなければ最小構造で新規作成し、壊れた JSON は原文をデータベースにバックアップしてから空オブジェクトとして再構築します（プロジェクトごとに直近 1 件）。書き込みは一時ファイル + 原子的リネームで行われます。紐付け・解除とも「先にデータベース、次にファイル」の二重書き込みで、ファイル書き込みが失敗してもデータベース行は残り、同期状態が修復を案内します。

ルーティングの意味論はソフトバインディングの 4 象限です。未紐付けのリクエストは従来と完全に同じ動作。フェイルオーバー無効かつ紐付けありなら紐付け先のみ。フェイルオーバー有効かつ紐付け先が健全なら紐付け先が先頭で共有キューが重複を除いて続き、失敗すれば委ねられます。紐付け先のブレーカーが開いていれば完全に共有キューへ譲ります。つまり紐付けは特定のプロバイダーを「先頭に上げる」だけで、共有の救済キューが無効になることは決してありません。紐付け検索そのものの失敗（データベースエラー）も未紐付けとして委ねられ、リクエストはブロックされません。

リクエストログは各記録に `project_dir`（送信元プロジェクトのパス）と `project_routed`（プロジェクト紐付けにヒットしたか）の 2 つの帰属フィールドを加え、プロジェクト列・「ルート」バッジ・プロジェクト絞り込みとして表示されます。同じ移行で `vision_routed`（画像ブランチのマーカー）も加わり、モデル列で「[画像]」バッジにより区別されます。本リリースにはデータベース移行が含まれます：`SCHEMA_VERSION` 19 → 21。`project_routes`（プロジェクト → プロバイダーの紐付け）と `settings_local_backup`（settings.local.json の書き込み前スナップショット）の 2 テーブルが新設され、リクエストログテーブルに列が追加されます。

## 追加

### プロジェクト単位のプロバイダールーティング

第一期は Claude アプリのみ（`app_type` が `claude`）で、エントリーボタンは Claude アプリがアクティブな間だけ表示されます。紐付けにはローカルプロキシのテイクオーバーが必要です。`X-CC-Project` マーカーはプロキシ経由のリクエストに乗るため、テイクオーバーなし（直接接続）では紐付けは何も変えず、既存の動作にも影響しません。

- **プロジェクト検出**：読み取り専用の 3 ソースを統合。`~/.claude.json` の `projects` キーが権威あるパス一覧（`lastSessionModified` がアクティビティを提供）、`~/.claude/projects/*/` の `*.jsonl` が補助的な cwd と mtime のアクティビティを提供（jsonl のない古い残骸ディレクトリはプロジェクトとみなさない）、`~/.claude/sessions/*.json` が現在アクティブなセッション（`busy`/`idle` など）を示します。パスごとに最大のアクティビティで統合し、ディレクトリが存在しないもの・30 日以上非アクティブなものを除外して、アクティビティ降順に並べます。`~/.claude.json` が欠損・破損しても jsonl ソースで縮退動作します。
- **紐付け UI**：各行にベース名（ホバーで完全パス）、「使用中」バッジ（アクティブなセッションがある場合）、相対アクティビティ時刻（ホバーで絶対時刻）、プロバイダー選択（「デフォルト（紐付けなし）」を含む）、同期バッジを表示。ページ表示中は 3 秒ごとにポーリングし、離れると停止します。
- **紐付けの書き込み**：紐付け = データベースの `project_routes` 行 + プロジェクトの `.claude/settings.local.json` の `X-CC-Project` 行の二重書き込み。解除は両方をクリア（ファイルや対象行がなければ黙って成功、冪等）。パスは UTF-8 バイト単位の percent-encode（`[A-Za-z0-9/._~-]` を保持し、他は `%XX`）で、結果は常に 1 行になり、改行などのヘッダー構文上敏感なバイトは必ずエスケープされます。存在しないプロバイダーへの紐付けは即座に失敗し、宙吊りの行は残しません。
- **ソフトバインディングの行列**：概要のとおり。健全な紐付け先が先頭に立ち共有キューが重複を除いて続き、遮断された紐付け先や紐付け検索の失敗は共有キューへ譲り、未紐付けの経路はバイト単位で従来どおりです。
- **削除の連鎖**：紐付けたプロバイダーを削除した後は、そのプロジェクトのリクエストは未紐付けとして共有キューに流れます。この種の宙吊り紐付けは「プロバイダー名 · 無効」と表示され、黙って消されることはありません。再紐付けかデフォルトへ戻すことで解消できます。
- **同期 3 状態とワンクリック修復**：`synced`（データベースの紐付けとファイルが一致）、`out_of_sync`（データベースに紐付けがあるがファイルが欠損・対象行なし・値不一致。ワンクリックでデータベースの紐付けに従ってファイル行を書き直します）、`orphan_header`（データベースに紐付けがないのにファイルに対象行が残っている。この行はルーティングに参加せず、表示のみ。クリアするかはあなた次第です）。

### リクエストログのプロジェクト帰属と絞り込み

プロキシ経由の各リクエストに送信元プロジェクトのパスとプロジェクト紐付けへのヒット有無が記録されます。リクエストログにプロジェクト列が加わり、紐付けにヒットしたリクエストには「ルート」バッジが付き、プロジェクトで絞り込めます。リクエスト詳細パネルにも同じ情報が表示されます。このフィールドは既存の意味ハッシュに参加しないため、旧データには影響しません。

### リクエストログの「[画像]」バッジ

画像ブランチ（vision ルート）を通ったリクエストは、これまでモデル列で通常のリクエストと区別できませんでした。今後は「[画像]」バッジで示され、モデルの流れは「[画像] 実モデル」と表示されます。古い記録にはマーカーがなく、バッジなしで表示されます。

## アップグレードノート

### 本リリースにはデータベース移行が含まれます

`SCHEMA_VERSION` 19 → 21 を 2 段階で進めます。v19 → v20 で `proxy_request_logs` に `vision_routed` 列を追加、v20 → v21 で `project_dir` と `project_routed` 列を追加します。あわせて `project_routes`（プロジェクト → プロバイダー紐付け。プロジェクト・アプリごとに最大 1 件）と `settings_local_backup`（settings.local.json の書き込み前スナップショット。プロジェクトごとに直近 1 件）の 2 テーブルを新設します。移行は初回起動時に自動で行われます。本バージョンを一度でも起動すると、v3.20.4 以前は「データベースが新しすぎる」として開けなくなります。ダウングレードするにはアップグレード前のバックアップを復元するしかありません。念のため、先に CC Switch を終了してから手動でコピーしてください：

```bash
cp ~/.cc-switch/cc-switch.db ~/cc-switch-before-v3.21.0.db
```

Windows では既定で `%USERPROFILE%\.cc-switch\cc-switch.db` にあります。設定で構成ディレクトリを変更している場合は、そこにデータベースがあります。

### 第一期は Claude アプリのみ、プロキシテイクオーバーが必要

プロジェクトルーティングは Claude アプリのみに適用され（Codex や Gemini などは未対応）、`X-CC-Project` による帰属はローカルプロキシ（テイクオーバー有効）を通るリクエストにのみ作用します。直接接続では紐付けは何も変えません。

### 紐付けと解除は新しいセッションで有効

`settings.local.json` は Claude Code がセッション開始時に読み込みます。紐付け・解除の後は **新しいセッション**（プロジェクトで Claude Code を開き直す）で新しいヘッダーが送られます。既存のセッションは起動時の環境を送り続けます。

### settings.local.json の変更方法

CC Switch が触るのは複数行の `env.ANTHROPIC_CUSTOM_HEADERS` 値の中の `X-CC-Project` 行だけです。他のヘッダー・他の env キー・トップレベルキーはバイト単位で保持されます。壊れたファイルは、原文をデータベースにバックアップしてから空オブジェクトとして再構築されます。書き込みのたびに書き込み前スナップショットが保存されます（プロジェクトごとに直近 1 件のみ）。書き込みはすべて原子的で、中途半端な状態は残りません。

### 未紐付けのプロジェクトの動作は不変

紐付けがひとつもなければ、すべてのリクエストのルーティングは v3.20.4 と完全に同じです。`orphan_header` の表示は、自分で紐付けた後にファイルを手で書き換えた場合にのみ現れ、クリアしてもファイルの他の内容には触れません。
