# CC Switch v3.21.0

> 这一版带来一项新能力：**按项目路由供应商**。在 Claude Code 里同时开工多个项目时，可以让每个项目固定走自己的供应商：CC Switch 从 `~/.claude` 的三处来源自动探测项目清单并合并出活跃度，你在新增的「项目路由」页面里把项目绑定到某个供应商；绑定写入项目自己的 `.claude/settings.local.json`，经本地代理发出的请求带上 `X-CC-Project` 标识后优先命中绑定的供应商。绑定是「软」的：绑定者失败时依序降级到公共故障转移队列，全部熔断时由公共队列救场，绑定的供应商被删除时自动回退。请求日志随之新增项目列、「路由」徽标与按项目筛选，另为走图片分支的请求补上「[图片]」徽标。首期仅覆盖 Claude 应用，且以开启代理接管为前提。**本版含数据库迁移（v19 → v21），建议升级前手动备份一次数据库**，见[升级提醒](#本版含数据库迁移)。

## 重点内容：你现在可以

- **给每个项目固定一个供应商**：新增「项目路由」页面（Claude 应用专属入口，位于会话浏览与 MCP 按钮之间）。每个项目一行：项目名、最近活跃时间、绑定供应商下拉、同步状态。选「默认（不绑定）」即回到全局路由。
- **不用手动登记项目**：项目清单从 `~/.claude` 三处来源自动探测——`~/.claude.json` 的 `projects` 键（权威路径清单）、`~/.claude/projects/*/` 下的会话 jsonl、`~/.claude/sessions/*.json` 的活跃标记——按活跃时间排序，超过 30 天未活跃的不入列；页面打开时每 3 秒自动刷新。
- **绑定失败不堵路**：软绑定语义。故障转移开启时，绑定者排在候选首位、公共队列依序垫后（去重），绑定者失败或熔断时请求降级到公共队列；全部熔断时公共队列照常救场；绑定的供应商被删除后，路由按无绑定走公共队列，页面显示「已失效」而不静默清空。
- **在历史记录里看到请求来自哪个项目**：请求日志新增项目列，经项目路由命中的请求带「[路由]」徽标，并支持按项目筛选。
- **一眼看出绑定与文件是否一致**：同步三态（已同步 / 未同步 / 孤儿行），「未同步」一键修复，「孤儿行」可选清除。
- **识别走图片分支的请求**：请求日志里经图片路由的请求在模型列显示「[图片]」徽标。

## 概览

「按项目路由供应商」解决的是多项目并行时的切换摩擦：此前供应商选择对整个应用是全局唯一的，换项目就得换卡片。现在 Claude Code 每个会话携带自己的项目身份——CC Switch 在项目目录的 `.claude/settings.local.json` 中，往 `env.ANTHROPIC_CUSTOM_HEADERS` 的多行值里注入一行 `X-CC-Project: <percent-encoded 路径>`——本地代理读到这个标识后，把请求路由到该项目绑定的供应商。

写入是克制的：只增删替换 `X-CC-Project` 这一行，同一多行值里用户自有的其他 header、文件里的其他顶层键与 env 键逐字节保留；文件不存在时新建最小结构，损坏的 JSON 会先按空对象重建、原文先入库备份（每项目保留最近一份）；落盘走临时文件 + 原子重命名。绑定与解绑都是「先数据库、后文件」的双写，文件写失败时数据库行保留，由同步状态兜底修复。

路由语义是「软绑定」四象限：未绑定的请求与现状完全一致；故障转移关闭且已绑定时只走绑定者；故障转移开启且绑定者健康时，绑定者置首、公共队列依序垫后（去重），绑定者失败即降级；绑定者熔断打开时完全让位公共队列——也就是说，绑定只是把某个供应商「提到队首」，永远不会让公共救场队列失效。绑定查询本身失败（数据库错误）也按无绑定降级，不阻塞请求。

请求日志为每条记录新增 `project_dir`（来源项目路径）与 `project_routed`（是否命中绑定路由）两个归因字段，界面呈现为项目列、「[路由]」徽标与项目筛选；同批迁移还为日志补上了 `vision_routed`（图片分支标记），模型列以「[图片]」徽标区分经图片路由的请求。本版含数据库迁移：`SCHEMA_VERSION` 19 → 21，新增 `project_routes`（项目 → 供应商绑定）与 `settings_local_backup`（settings.local.json 写前快照）两张表，并为请求日志表加列。

## 新功能

### 按项目路由供应商

首期仅覆盖 Claude 应用（`app_type` 为 `claude`）；入口按钮只在 Claude 应用激活时出现。绑定以本地代理接管为前提：`X-CC-Project` 标识经代理请求携带，未接管（直连）时绑定不生效，也不影响任何现有行为。

- **项目探测**：三源合并扫描，全部只读。`~/.claude.json` 的 `projects` 键是权威路径清单（`lastSessionModified` 提供活跃时间）；`~/.claude/projects/*/` 下的 `*.jsonl` 提供补充 cwd 与文件 mtime 活跃度，无 jsonl 的陈旧残留目录不算项目；`~/.claude/sessions/*.json` 标记当前活跃会话（`busy`/`idle` 等）。三源按路径归并取最大活跃时间，项目目录不存在或超过 30 天未活跃的过滤掉，结果按活跃时间降序。`~/.claude.json` 缺失或损坏时靠 jsonl 源降级工作。
- **绑定界面**：项目列表每行展示 basename（悬浮显示完整路径）、「使用中」徽标（有活跃会话时）、相对活跃时间（悬浮显示绝对时间）、绑定供应商下拉（含「默认（不绑定）」）与同步状态徽标。页面打开时每 3 秒轮询刷新，切走即停。
- **绑定写入**：绑定 = 数据库 `project_routes` 行 + 项目 `.claude/settings.local.json` 的 `X-CC-Project` 行双写；解绑双清（文件缺失或无目标行时静默成功，幂等）。路径经 UTF-8 字节级 percent-encode（保留 `[A-Za-z0-9/._~-]`，其余转 `%XX`），编码结果恒为单行，换行等 header 语法敏感字节必然被转义。绑定到不存在的供应商会立刻报错，不留悬空行。
- **软绑定路由矩阵**：见上文「概览」。绑定者健康时置首、公共队列去重垫后；绑定者熔断或绑定查询失败时让位公共队列；未绑定路径逐字节与现状一致。
- **删除级联回退**：绑定的供应商被删除后，该项目的请求按无绑定走公共队列；项目路由页对这类悬空绑定显示「供应商名 · 已失效」，不会静默清空，换绑或改回默认即可消除。
- **同步三态与一键修复**：`synced`（数据库绑定与文件一致）、`out_of_sync`（数据库有绑定但文件缺失、无目标行或值不一致，提供一键修复——按数据库绑定重写文件行）、`orphan_header`（数据库无绑定但文件残留目标行；该行不参与路由，仅提示，可选清除）。

### 请求日志的项目归因与筛选

每条代理请求记录新增来源项目路径与是否命中绑定路由两个字段。请求日志表新增项目列，命中项目路由的请求带「[路由]」徽标，列表支持按项目筛选；请求详情面板同步展示。字段不参与现有语义哈希，旧数据不受影响。

### 请求日志的「[图片]」徽标

走图片分支（vision 路由）的请求此前在模型列与普通请求无从区分，现在以「[图片]」徽标标注，模型链路展示为「[图片] 实际模型」。旧记录无此标记，按无徽标展示。

## 升级提醒

### 本版含数据库迁移

`SCHEMA_VERSION` 19 → 21，分两步：v19 → v20 为 `proxy_request_logs` 添加 `vision_routed` 列；v20 → v21 为其添加 `project_dir` 与 `project_routed` 列。另新建 `project_routes`（项目 → 供应商绑定，每项目每应用至多一条）与 `settings_local_backup`（settings.local.json 写前快照，每项目保留最近一份）两张表。迁移在首次启动时自动运行。运行过本版之后，v3.20.4 及更早的版本会以「数据库版本过新」为由拒绝打开，想降级只能恢复升级前的备份。稳妥起见，升级前先退出 CC Switch，手动复制一份：

```bash
cp ~/.cc-switch/cc-switch.db ~/cc-switch-before-v3.21.0.db
```

Windows 上默认在 `%USERPROFILE%\.cc-switch\cc-switch.db`。如果你在设置里改过配置目录，数据库就在那个目录下。

### 首期仅 Claude 应用，且需开启代理接管

项目路由只对 Claude 应用生效（Codex、Gemini 等暂不覆盖），并且只有请求经本地代理（接管开启）时才按 `X-CC-Project` 归因路由。直连场景下绑定不会改变任何行为。

### 绑定与解绑对新会话生效

`settings.local.json` 是 Claude Code 启动会话时读取的：绑定或解绑后，需要**新开一个会话**（重开当前项目里的 Claude Code）才会带上新的 header。已存在的旧会话继续按启动时的环境发送。

### settings.local.json 的修改方式

CC Switch 只动 `env.ANTHROPIC_CUSTOM_HEADERS` 多行值里的 `X-CC-Project` 行，你的其他 header、其他 env 键与顶层键逐字节保留。文件损坏时按空对象重建，重建前原文已入库存份；每次写前也都会保存写前快照（每项目仅最近一份）。写入均为原子落盘，不会出现半写状态。

### 未绑定的项目行为不变

没有任何绑定时，所有请求的路由与 v3.20.4 完全一致；`orphan_header` 提示只在你主动绑定又手动改过文件时出现，清除它不会动文件的其他内容。

## 风险提示

### 沿用的提示

**第三方供应商路由**：通过 CC Switch 本地代理把 Claude Code、Codex、Claude Desktop 或 Grok Build 的请求转换并转发到第三方供应商时，各供应商对计费、合规与数据留存的约束不同，请在使用前阅读目标供应商的服务条款。项目路由会把特定项目的全部请求固定到同一供应商，多项目共用同一账号额度时请注意配额分布。

用户启用上述功能即表示自行承担相关风险。CC Switch 不对因使用这些功能而导致的任何账号限制、警告或服务暂停承担责任。
