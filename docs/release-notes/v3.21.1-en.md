# CC Switch v3.21.1

> Fixes a distracting issue on the "Project Routing" page: every 3-second refresh could reshuffle the list — a row jumping "here one moment, there the next" — the more projects, the worse it got. Sorting is now fully deterministic: projects active at the same second are ordered by path, so rows stay put.

## Fixes

### Project Routing list reshuffling on refresh

The "Project Routing" page sorts projects by last-active time, descending. With activity normalized to second-level precision, multiple projects landing on the same second is common (used on the same day, session files with the same-second mtime, and so on); the sort previously had no rule for ties, so the relative order within a tie fell back to the random iteration order of an internal unordered hash map — the page rescans every 3 seconds, and each rescan reshuffled the tie group. Rows kept drifting up and down, glaringly so on machines with many projects.

The fix: projects active at the same second are now tie-broken by project path (lexicographic). Paths are unique, the sort is therefore fully deterministic, and positions stay constant across refreshes; when activity genuinely changes, a project still moves as expected. Affects only the "Project Routing" page of the Claude app. No database migration; nothing else changes.
