# CC Switch v4.1.0

This release lets session management work with SSH remote hosts: add a Linux/macOS server in Settings, and the session page can switch between "Local" and the remote host in one click, showing the claude and codex session history on that machine, with the list, reading, pagination, compressed sessions, images, export and deletion all working the same as locally. Connections use passwordless authentication only and reuse SSH ControlMaster; remote session summaries and parsing have an incremental cache, so a second scan of an unchanged session makes no network requests. GNU find and BSD/macOS remotes are both supported automatically, a missing session directory on the remote is tolerated, and on Windows without OpenSSH the feature entry degrades to an install hint. Remote access accepts passwordless credentials only and stores no passwords, all remote paths are escaped against injection, and remote deletion is guarded by a whitelist. For everything new in 4.0, see the [v4.0 release notes](https://github.com/farion1231/cc-switch/blob/main/docs/release-notes/v4.0.4-en.md).

**Release date**: 2026-11-08

## New

### Managing sessions on remote hosts

Session management used to show only local sessions; to see claude or codex sessions running on a server, you had to sign in to the server or copy the files back by hand.

Now "Settings → SSH Hosts" lets you add remote machines:

- **Import from SSH Config**: reads the Host entries in `~/.ssh/config` in one go and imports the ones you pick; you can also switch to "Add manually" and enter the host address, username, port and identity file (the last three optional).
- **Test connection**: both when adding and editing, you can check connectivity first, instead of finding out it does not connect after filling everything in.
- Deleting a host only removes it from the list; its remote session cache is kept, and after re-adding the same host you can pick up where you left off.

Once added, the session page switches between "Local" and a remote host in one click. On a remote host, the claude and codex session history works exactly like the local one: the session list, reading, pagination, `.zst` compressed sessions, embedded images, export and deletion all work as usual, with the same interactions.

- Both GNU find (Linux) and BSD find (macOS) remotes are supported; nothing needs to be installed on the server.
- When the remote does not have a session directory yet, it is tolerated and shown as empty instead of an error.
- On Windows without the OpenSSH client, the host selector prompts to install OpenSSH first; local sessions are not affected.

### Security boundaries of remote access

- **Passwordless authentication**: connections use only the passwordless credentials SSH already has (keys and the like); CC Switch stores no passwords and never asks for one in the interface.
- **Path injection protection**: every path sent to the remote is escaped, so special characters in host names and paths cannot be assembled into extra commands.
- **Deletion whitelist**: remote deletion only allows session files from the current scan list; any path outside the list is refused, protecting other files on the remote from being deleted by mistake.

## Changes

- **Performance**:
  - SSH connections reuse ControlMaster: once the first connection is up, listing, reading and export reuse the same connection instead of a fresh handshake for every command.
  - Remote session summaries and parsing have an incremental cache: when a session's content fingerprint is unchanged, a second scan makes zero network requests and uses the local cache.
- **Internal**:
  - The transport layer's 40MB output cap is aligned with the semantic layer.
  - The 13 local session scanners are unchanged, so local session behavior is unaffected.
  - Testing was expanded considerably: more Rust and frontend tests, plus a localhost SSH end-to-end integration smoke test.

---

## Known limitations

- Searching message text is not yet available for remote sessions (metadata search such as titles and session IDs works); it will come in a later release.
- Agents that store sessions in SQLite, such as opencode and hermes, cannot be viewed remotely yet; support is planned for a later release.
